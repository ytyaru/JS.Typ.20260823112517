# Number型における安全な浮動小数点数の範囲を算出する方法

````markdown
jsのNumber型について。丸め誤差を考慮した上で、少数部を少なくとも1桁は保証できる上限、下限の値はいくつか。`999999999999999`〜`-999999999999999`と考えて良いか？

`9007199254740991-0.1`だと`9007199254740991`になってしまい丸め誤差によって少数部が消えてしまう。つまり少数1桁を保つことができない。これはダメだ。

16桁の場合は少数値が保てない場合が発生する。だが`1000000000000000+0.1`では正しく`1000000000000000.1 `になる。16桁は不安定。

15桁は必ず1桁が保証される。`999999999999999+.1`だと`999999999999999.1`。`-999999999999999-0.1`だと`-999999999999999.1`。だが`999999999999999+.123456789`だと`999999999999999.1`で小数部が桁落ちする。しかし丸め誤差が発生しようとも小数部を少なくとも1桁は確実に保証されている。故に`999999999999999`〜`-999999999999999`の範囲が求める範囲であることは分かる。

だがそれは十進数基準だ。IEEE754は二進数のはず。では、少数部を少なくとも1桁は保証できる***正確な***上限、下限の値はいくつだ？　ギリギリまで攻めると`999999999999999`〜`-999999999999999`の範囲よりも大きいはずだと思っている。どうやって算出すればいい？

次のような便利関数が欲しい。

```javascript
// Number型における十進数からみた桁数で安全に扱える範囲を返却する: return [min, max]
function getFloatRange(f) {// v:検査対象となるNumber型の値, f:小数部の最長桁数
    // fはnumber型の整数であり1以上の正数（自然数）のはず。しかも15桁を超えると少数を安全に扱えなくなる。丸め誤差によって整数化されてしまうから。このようにfが安全に少数を扱えなくなった場合は例外発生する。他にも必要に応じてエラーハンドリングすること。
    return [min, max];
}
```
```javascript
const [min, max] = getFloatRange(1); // -999999999999999〜999999999999999等（多分これより大きい範囲になるはず）
```
````

## 回答

```
/**
 * Number型における十進数からみた指定小数桁数を安全に扱える範囲を返却する
 * @param {number} f - 小数部の最長桁数（1以上の整数）
 * @returns {[number, number]} [min, max] の範囲
 */
function getFloatRange(f) {
    // 引数のバリデーション
    if (!Number.isInteger(f) || f < 1) {
        throw new Error("小数部の桁数 f は1以上の整数である必要があります。");
    }
    
    // IEEE 754で安全に少数を扱える限界（一般に15桁〜17桁付近が境界）
    // 10^f が (2^53 - 1) を超えると、小数部を安全に保持する余裕がなくなるため例外とする
    const maxSafeInt = Number.MAX_SAFE_INTEGER; // 9007199254740991
    const factor = Math.0 * Math.pow(10, f); // 厳密なべき乗
    
    if (factor > maxSafeInt) {
        throw new Error(`小数部 ${f} 桁は安全な精度限界を超えているため扱えません。`);
    }

    // 整数部と小数部を合わせた総ビット数から、許容される最大の整数境界を算出
    // 最大整数値は (2^53 - 1) を 10^f で割ったものの整数部
    const max = Math.floor(maxSafeInt / factor);
    const min = -max;

    return [min, max];
}
```
