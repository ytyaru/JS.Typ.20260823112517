# エラーメッセージ時の期待値を型名で表示したい

コードのファイルサイズ増大を最小限にしながら実現したい。

現状、fn-obj.jsで実装している。some系メソッドと固有型メソッドの例外メッセージは以下のように微妙に違う。

some系
```
Expected: a value that makes '${pathStr}' return true.\nActual: ${Tys.name(v)}
```
個別型
```
Expected: '${val.toString()}' like value.\nActual: ${Tys.name(v)}
```

上記の通り、個別型の場合は型名でなくソースコードの内容を表示することになっている。これを型名表示に変更したい。

また、両者のソースコードを以下のように一つにまとめたい。

共通化
```
Expected: ${ExpectedMessage}\nActual: ${Tys.name(v)}
```

いずれにせよsome系は単一の型名を明示できない。some系は複数の型名のいずれかであるかを判定するAPIだから。結局メッセージは分けることになる。だが実装は一つのコードにまとめて重複コードを排除しコード量を減らしたい。

問題は個別型の名前だ。これを表示するにはどうしても型名のリテラル記述を増やさねばならない。故にファイルサイズは増加してしまうだろう。なるだけその増加量を抑えながら、型名表示に変えたいというのが主旨だ。

上記マスターデータから以下を統一的に実現するコードを書きたいのだが、論理的に可能か？可能ならコードを書け。不可能なら理由を説明しろ。

1. 全メソッドを実装する
	1. FnObjを生やす
		1. some系メソッドを呼び出す
		2. プロパティを生やす
			1. 個別メソッドをセットする
2. エラー時の期待値メッセージ
	1. `some`系なら`path`を使ってメッセージを作る
	2. 個別型なら型名（キー名）を表示する

でもDATAの中にはTys依存が残っている。Tys.nameの中には判定用コードと型名がある。Tysで使うその定義部分を抜き出したものがマスターデータのコアになるはずだ。但し、他の型判定との順序を含めた因果関係がなければ個別型判定式を実現できないものが多数ある。それに関してはマスターデータ化できない。

例えば`Null`型に関しては`if (null===v) return 'Null';`で独立できる。だが`PlainObject`に関しては他のオブジェクト型でないことを判定せねばならない。他の判定式と複雑に入り組んでおり独立した判定式を抜き出すことが難しい。力技でやれば可能だが、他の判定式の部分が重複コードとして大量発生してしまう。循環参照の危険もある。故にtys.jsの中から独立した型判定が可能な式と型名のみをまずは抽出したい。それが以下。
