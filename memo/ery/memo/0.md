# Ery

## 名前

`Ery = Error Factory`。

## 概要

独自のエラー体系を構築する。

## 課題

* エラーの特定
	* 型だけでは特定できない
		* Realmの違いにより`instanceof`で特定できない
		* `name`プロパティだけでも特定できない（プレーンオブジェクトでnameをもちたまたま同じ値であれば同じ型であると誤判定されてしまう。だがRealmをまたいだときはこれしか判定できない。故にBunのテストAPIであるtoThrow(e)はnameで判定している）
	* メッセージは国際化に阻まれ特定すべき要素に含めるべきでない

## 解法案

型とcodeで例外を一意に特定できるようにする。

```
const SYMBOL = Symbol();
class MyError extends Error {
	constructor(S, code, message, cause) {
		if (S!==SYMBOL) {throw new Error(`newできません。MyError.throw(code)で例外発生させてください。`)}
		super(message, cause ? {cause} : undefined);
		this.name = 'MyError';
	}
	static #codes = [1,2,3];
	static get codes() {return this.#codes;}
	static #validCode(code) {if (!this.#codes.includes(code)) {throw new Error(`codeが不正値です。実際値:${code} 期待値:${this.#codes}`)}}
	// Realm差異を考慮してinstanceof Errorは使わない
	static #validErrIns(e) {if (!(null!==typeof e && 'object'===typeof e && 'name' in e && 'code' in e)) {throw new TypeError(`引数はErrorインスタンスであるべきです。`)}}
	static #hasAllKeys(obj) {
		for (let code of this.#codes) {
			if (!Object.hasOwn(code)) {throw new Error(`全キーのうち次のキーを持っていません: ${code}`)}
		}
	}
	static throw(code, ...args) {
		this.#validCode(code);
		throw new MyError(SYMBOL, code, this.getMessage(code, ...args));
	}
	static is(e, code) {
		this.#validErrIns(e);
		return MyError.name===e.name && undefined===code ? true : this.#validCode(code);
	}
	static #DEF_PTN_KEY = '_';
	static match(e, obj) {
		this.#validErrIns(e);
		if (!Object.hasOwn(#DEF_PTN_KEY)) {this.#hasAllKeys(obj);}
		if (![e.code, #DEF_PTN_KEY].some(x=>Object.hasOwn(x))) {throw new Error(`パターン指定であるobjの網羅ができていません。プロパティに指定コードがなく、デフォルト処理用プロパティ'${#DEF_PTN_KEY}'もありません。: ${e.code}`}
		return obj[Object.hasOwn(e.code) ? e.code : #DEF_PTN_KEY]();
	}
	static try(fn, obj, fin) {try {fn();} catch (e) {return this.match(e,obj);} finally {if(fin) ? fin() : null;}}
}
```

これを自由に作れる汎用APIにしたい。例えば以下みたいな？

単一固定メッセージのみ。
```
Ery.make('MyError', '固定メッセージ');
```
```
MyError.throw(); // new MyError('固定メッセージ')
```

単一変動メッセージのみ。
```
Ery.make('MyError', (...args)=>`変動メッセージ: ${...args}`);
```
```
MyError.throw(someValue); // new MyError('変動メッセージ: ...')
```

複数メッセージがある場合。
```
Ery.make('MyError', {
	100: `異常1`,
	101: `異常2`,
	102(arg) {return `異常3: ${arg}`}
	103(arg) {return 'number'===typeof arg ? `異常4: ${arg}` : `構造が違うメッセージ`;}
});
```
```
MyError.throw(100); // new MyError('異常1')
MyError.throw(102, 'X'); // new MyError('異常3: X')
```

`new`はさせない。これにて例外の種別を完全特定できる。普通は例外が発生したcatch構文内で特定したいはず。特定APIはis、match、tryの3つある。以下のように使う。

```
try {...}
catch(e) {
	if (MyError.is(e)) {
		if (MyError.is(e, 100)) {
			// 任意処理
		}
		else if (MyError.is(e, 101)) {
			// 任意処理
		}
	}
	if(e instanceof OtherError) {...}
}
```
```
try {...}
catch(e) {
	MyError.match(e, {
		100: ()=>エラー100時の処理,
		101: ()=>エラー101時の処理,
		_: 上記以外のエラー時の処理,
	});
	if(e instanceof OtherError) {...}
}
```
```
MyError.try(()=>MyErrorが発生しそうな処理, {
	100: ()=>エラー100時の処理,
	101: ()=>エラー101時の処理,
	_: 上記以外のエラー時の処理,
}, ()=>finallyで実行したい処理があればこれを作って渡す);
try {...}
catch(e) {
	if(e instanceof OtherError) {...}
}
```

codeに相当するのはNumberでなくStringでも良いことにすべきか。どの型にするか定義できるようにすべきか。

```
❯ let x = {100:'n', 001:'x'}
{
  "1": "x",
  "100": "n",
}
```

以下のようにTSVで一括指定できると楽だが。テンプレートリテラルまでならいいが、それ以上に複雑なメッセージ構築をする必要がある場合には対応できない。

```tsv
#code	message
000	異常1
001	異常2
101	異常3
201	異常4: ${x}
301	異常5: 引数次第で別のメッセージになるようコードで実装したい時は、この方法じゃ実装できない！
```

そんな複雑系メッセージだけはJSコードで後付で追加するようにしたいが。APIが複雑化しそうだ。

```
Ery.make('MyError', `
#code	message
000	異常1
001	異常2
101	異常3
201	異常4: ${x}		これは引数xがあると想定して内部で自動的にそう実装する
`,
{
	301(x){return 'number===typeof x ? 'テンプレートリテラルでは対応できないような' : '全然違うメッセージにしたい場合もあるよね'}
});
```

構造やメッセージの複雑さに応じて引数を追加できる形にするのが妥当か。
